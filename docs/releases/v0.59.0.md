# AFService Map v0.59.0

Backup/ponto de rollback desta rodada: tag `v0.58.1`.

Depois de testar o editor de dashboard (v0.55.0-v0.57.0) e o whitelabel
(v0.55.0, ajustado na v0.58.1), o pedido foi: deixar o dashboard
redimensionável de verdade, arrastando a borda de cada card — como
Zabbix ou Grafana, não só tamanhos fixos.

## Principais mudanças

### Adicionado

- **Dashboard redimensionável.** O editor de widgets (dashboard de
  empresa, do projetista, e "Visão da plataforma" do superusuário) deixa
  de ter zonas fixas (cartões numa faixa, painéis em 2 colunas) e passa a
  ser um grid livre de 12 colunas: qualquer widget pode ser arrastado pra
  qualquer posição e redimensionado livremente pelo canto. Esconder/
  mostrar widget e a mensagem opcional no topo continuam do jeito que
  estavam.
- **Só o modo de edição ganha peso.** A biblioteca nova (Gridstack.js,
  carregada via CDN) só é usada enquanto alguém está editando — a mesma
  ideia já aplicada ao SortableJS que ela substitui. Quem só **vê** o
  dashboard normalmente não carrega nenhuma biblioteca de layout: o
  servidor já sabe a posição/tamanho salvo de cada widget e desenha tudo
  com CSS Grid comum, sem depender de JavaScript pra isso.

### Técnico

- `CompanyDashboardLayout`/`PlatformDashboardLayout` trocam
  `widget_order` + `hidden_widgets` (duas listas) por um campo só,
  `widget_layout` — posição (x, y), tamanho (w, h) e visibilidade de
  cada widget num dicionário. Migration com conversão automática dos
  layouts já salvos antes desta versão (mantém a ordem relativa e o que
  estava escondido, calculando uma posição/tamanho padrão pra cada um).
- Widget sem posição salva ainda (dashboard novo, ou widget que apareceu
  depois da última vez que alguém editou) recebe posição automática
  (auto-flow) — mesmo espírito de "ordem padrão" de antes, agora em duas
  dimensões.

## Atualização

Execute `apply` no servidor. **Esta versão tem migration** (converte os
layouts salvos) — o `entrypoint.sh` já roda `migrate` sozinho.

Teste sugerido:
1. Abrir "Editar dashboard" numa empresa que já tinha personalizado o
   layout antes desta versão — confirmar que a ordem e o que estava
   escondido continuam corretos (convertidos automaticamente).
2. Redimensionar um card puxando o canto, mover outro pra uma posição
   diferente, salvar, sair do modo de edição e recarregar — confirmar
   que o tamanho/posição bateram.
3. Testar num board novo (sem nada salvo ainda) — os widgets devem
   aparecer numa disposição padrão razoável, sem sobreposição.
4. Conferir em tela estreita/mobile que os widgets empilham em 1 coluna.
