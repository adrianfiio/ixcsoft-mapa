# AFService Map v0.70.0 — Mapa Master Suite

Backup/ponto de rollback desta rodada: tag `v0.69.0` (também disponível
como branch `backup/mapa-pre-master-suite-20260801`). Pacote cumulativo
"Master Suite v1.0.0" preparado pelo ChatGPT para a área do mapa,
aplicado aqui via `apply_map_master_suite.py` (validado antes com
`--dry-run`, sem erro).

**Tem migration** — `network_map/0032_map_master_suite` — explicada em
detalhe mais abaixo, porque essa é a parte que precisa de atenção antes
do `apply`.

## Duas correções feitas nesta rodada (antes de liberar)

**Conflito de nomes entre `apps/network_map/services.py` e
`apps/network_map/services/`.** O pacote trazia um novo módulo em
`apps/network_map/services/map_master_topology.py`, mas o repositório já
tinha `apps/network_map/services.py` (arquivo, não pasta) em uso ativo há
tempo. Python não aceita um módulo e um pacote com o mesmo nome
convivendo no mesmo diretório. Resolvido movendo o arquivo novo pra
`apps/network_map/map_master_topology.py` — mesmo padrão "plano" dos
outros arquivos do pacote (`map_master_models.py`, `map_master_admin.py`)
— e ajustando os dois lugares que importavam do caminho antigo
(`apps/network_map/api/map_master_views.py` e
`apps/network_map/tests/test_map_master_suite.py`).

**Migration escrita à mão.** Este ambiente onde preparo os pacotes não
tem GDAL nem um banco PostGIS rodando (é só o repositório de código),
então `python manage.py makemigrations` não funciona aqui — nunca
funcionou, todos os testes que dependem de banco sempre foram deixados
pro servidor. Desta vez, como o pacote inclui 3 modelos novos, escrevi a
migration manualmente (`apps/network_map/migrations/0032_map_master_suite.py`)
transcrevendo os campos exatos de `MapIconStyle`, `MapDiagramRevision` e
`NetworkAssetLifecycle`, mais as novas opções de `equipment_type`/
`port_type` (que não geram nenhuma mudança real de schema — `choices`
não é validado pelo banco, só registra o estado pro Django parar de
avisar que há mudança pendente). **Antes de rodar `migrate` de verdade,
vale conferir no servidor:**

```bash
docker compose exec web python manage.py showmigrations network_map
docker compose exec web python manage.py sqlmigrate network_map 0032_map_master_suite
```

Isso mostra o SQL exato que vai rodar, sem aplicar nada — só criação de
3 tabelas novas e 2 `ALTER COLUMN` cosméticos (mudança de `choices`, sem
efeito no schema). Se algo parecer estranho, pare e me avise antes de
migrar.

## O que entrou

### Rotas conectadas de verdade

Antes, uma rota aparecia no painel por proximidade/nome importado. Agora
só aparece quando existe uma cadeia realmente conectada: POP/Rack/Torre
com OLT ou DIO → cabo com as duas pontas → CEO/CDO/CTO conectada → demais
trechos contínuos. O sistema identifica e explica: cabo desconectado,
cabo com uma ponta só, trecho isolado, falta de origem OLT/DIO, falta de
caixa conectada. A rota passa a se atribuir direto no cabo (e nos demais
elementos), com "Definir rota"/"Sem rota definida" nos popups.

### Ícones configuráveis pelo Django Admin

Novo item **Estilos de ícones do mapa** no `/admin/`: SVG, URL de imagem,
cores (frente/fundo/borda), tamanho e se mostra o nome dentro do ícone —
tudo por empresa. Depois do `migrate`, rode:

```bash
docker compose exec web python manage.py seed_map_icon_styles
```

Isso popula os estilos padrão (CTO, CEO, CDO, Rack, Torre, Poste, PTO)
pra todas as empresas — sem isso os ícones caem no visual padrão embutido
no JS.

### Editor de POP/Rack/Torre com 5 abas

Equipamentos, **Canvas 2D** (arrastar equipamento, posição persiste,
organização automática, ligações ancoradas nas portas, caminhos
ortogonais, pontos de dobra editáveis, tela cheia, exportar PNG), Matriz
de manobra, Fibras e terminações, YAML/modelos.

### Inventário técnico ampliado

Roteador, firewall, servidor, ONU/ONT e PTO agora são tipos reais de
equipamento (antes ONU/PTO eram salvos como "outro" com metadado à
parte). Portas novas: RJ45 2.5G, SFP28 25G, QSFP+ 40G, QSFP28 100G,
SC/APC, SC/UPC, LC. Campos novos no equipamento: fabricante, modelo,
série, patrimônio, IP, firmware, função, posição/altura em U, face do
rack, foto, documentação, uplinks, potência TX, observações — mais
módulos (SFP/SFP+/SFP28/QSFP/DAC/GBIC) nas placas de OLT.

### CTO e splitters

Reaproveita splitters/portas já existentes em vez de recriar; estados
livre/reservada/ocupada/defeituosa; vínculo com cliente/AccessPoint;
observações por porta; ficha técnica.

### Rastreamento óptico

Grafo considerando elementos, cabos, fibras, fusões, splitters, portas
internas, equipamentos e ligações (fibra/cobre/wireless) — tela
"Rastrear" mostra o caminho entre origem e destino com nomes de fibras,
cabos, equipamentos e portas.

### Fichas, QR Code e histórico

Botão "Ficha/QR" em elementos, cabos e equipamentos: ficha técnica
imprimível, QR Code em SVG que abre o ativo direto no mapa, estados de
implantação (em projeto/não implantado/implantado/certificado/
desativado) e histórico com usuário, data e observação.

### Editor de fusões e desempenho

Janela mais compacta e móvel, maximização por CSS que não abre mais pela
metade e não cai ao usar splitter/nota/menu, botão "Desmaximizar"
funcionando e reposicionando a janela na tela. Removido mais um
`MutationObserver` que observava o documento inteiro (o do seletor YAML
em `map-v092.js`) — reduz chance de travamento em projetos grandes.

### Corrigido

- Clique em "Inserir caixa" que criava a caixa mas não continuava: a API
  já devolvia `id` na raiz da resposta, o código só olhava
  `result.element.id`. Também: cliques duplicados bloqueados, popup
  fechado antes de inserir, cancelamento com Esc, ação não fica mais
  presa pro próximo clique.
- Remoção de cabo de uma caixa específica (sem apagar do mapa), com
  proteção contra remover cabo que termina fisicamente ali.
- Repetição visual "CDO CDO" no ícone.
