## Corrigido

- **`consultar_status.py` adicionado ao `.gitignore`.** Nada foi movido
  ou apagado — só parou de aparecer no `git status`.

## Sugestão pra não repetir isso toda hora

Scripts novos do projeto de monitoramento continuam aparecendo soltos
dentro de `/opt/ixcsoft-mapa`, que é a pasta do checkout do Git deste
projeto — cada script novo desses bloqueia o `apply` até alguém (eu)
adicionar no `.gitignore` e o servidor conseguir puxar a atualização.
Se os próximos scripts desse projeto (Influx/SNMP/Telegraf) forem
criados direto numa pasta separada, por exemplo `/opt/monitoring/`, em
vez de dentro de `/opt/ixcsoft-mapa`, esse problema para de acontecer de
vez — sem precisar de mais nenhum ajuste de `.gitignore` no futuro.

## Atualização

Execute `apply` no servidor. Como o servidor ainda não puxou este
`.gitignore` novo, este primeiro `apply` só funciona movendo o arquivo
pra fora temporariamente:

```bash
mkdir -p /root/monitor-staging
mv consultar_status.py /root/monitor-staging/
apply
mv /root/monitor-staging/consultar_status.py .
```

Sem migration nesta versão.
