# AFService Map v0.50.1

Backup/ponto de rollback desta rodada: tag `v0.50.0` no GitHub.

Correção de observabilidade: precisamos ver o erro 500 do "Excluir projeto"
e os logs do servidor não mostravam nada além da linha de acesso.

## Principais mudanças

### Corrigido

- Com `DEBUG=false` (o modo de produção), o Django só registra erros 500
  mandando e-mail para `ADMINS` — sem essa configuração, o traceback do
  erro não aparece em lugar nenhum, nem em `docker compose logs`. Adicionei
  um `LOGGING` explícito no `settings.py` que sempre imprime o traceback
  completo no console, independente de `DEBUG`. Isso não resolve nenhum bug
  específico por si só — é o que faltava pra conseguirmos investigar o erro
  500 ao excluir um projeto pelo painel de administração.

## Atualização

Execute `apply` no servidor. Sem migration nesta versão. Depois de aplicar,
reproduza o erro (clique em "Excluir projeto" de novo) e rode
`docker compose logs web --tail 150` — agora deve aparecer o traceback
completo do Python logo depois da linha `... 500 ...`.
