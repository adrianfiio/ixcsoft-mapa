# AFService Map v0.48.1

Backup/ponto de rollback desta rodada: tag `v0.48.0` no GitHub.

Adiciona um comando de manutenção para zerar a estrutura de rede de um
projeto (útil pra testar o assistente de importação KML/KMZ do zero, sem
apagar o projeto em si).

## Principais mudanças

### Adicionado

- **`wipe_network_project`**: apaga postes, CTOs, CEOs/CDOs, racks, DIOs,
  OLTs, cabos (com tubos, fibras, reservas e passagens ligados a eles),
  splitters, fusões, rotas, POP e lotes de importação KMZ de **um** projeto
  — o projeto em si (nome, código, empresa) continua existindo, só fica
  vazio. Segue o mesmo padrão de segurança do `reset_company_imported_data`
  que já existe no projeto:
  - roda em modo simulação por padrão, mostrando a contagem de tudo que
    seria apagado, sem apagar nada;
  - só apaga de verdade com `--confirm <código-do-projeto>` (o código exato
    aparece na simulação);
  - tudo dentro de uma transação: se der erro no meio, nada é apagado.

## Como usar

```bash
# 1. Simulação — mostra o que seria apagado, sem apagar nada
docker compose exec web python manage.py wipe_network_project "SUL-JANDAIA DO SUL"
docker compose exec web python manage.py wipe_network_project "TESTE"

# 2. Depois de conferir a contagem, apaga de verdade
docker compose exec web python manage.py wipe_network_project "SUL-JANDAIA DO SUL" --confirm <CÓDIGO-MOSTRADO-NA-SIMULAÇÃO>
docker compose exec web python manage.py wipe_network_project "TESTE" --confirm <CÓDIGO-MOSTRADO-NA-SIMULAÇÃO>
```

O primeiro argumento aceita o nome OU o código do projeto (o mesmo texto
que aparece no seletor de projetos do mapa); se dois projetos tiverem nomes
parecidos, o comando avisa e pede pra usar o código exato.
