# AFService Map v0.60.0

Backup/ponto de rollback desta rodada: tag `v0.59.0` no GitHub (também
disponível como branch `backup/mapa-pre-v08-20260801`).

Pacote da área do mapa/KMZ/estruturas internas preparado pelo ChatGPT
("v0.8" na numeração dele) e aplicado aqui via script próprio
(`apply_v08.py` — patches exatos em cada arquivo, com backup automático
antes de tocar em qualquer um; todos aplicaram sem conflito). Seguindo a
divisão de trabalho combinada: essa área é responsabilidade do ChatGPT,
aqui só recebe, aplica e publica.

## Principais mudanças

### Corrigido

- **A geração de fibras ainda podia falhar com "O modelo do cabo não
  possui padrão de cores"**, mesmo depois do fallback já corrigido na
  v0.56.0. A causa real: um gerador de fibras antigo
  (`apps/optical/services/fiber_generator.py`), disparado por um signal
  automático ao criar o `FiberCable`, interrompia a criação do cabo
  ANTES de o importador conseguir aplicar o próprio fallback. Esse
  gerador antigo virou um adaptador fino do serviço correto
  (`generate_cable_fibers`), com o mesmo fallback de sempre (padrão do
  modelo → paleta de cores cadastrada → paleta técnica automática). O
  importador também passou a checar se o signal já gerou a estrutura
  antes de tentar gerar de novo, pra não duplicar.
- Abrir "Gerenciar estrutura" numa torre/rack não recarrega mais o mapa
  inteiro — mesma correção de concorrência com o popup do Leaflet já
  aplicada às Fusões na v0.56.0.

### Adicionado

- **Torre e rack aceitam mais equipamentos.** Torre: Switch, Access
  point, Rádio PTP, DIO e ONU/ONT/Outro. Rack: OLT, DIO, Switch e
  ONU/ONT/Outro. Sem migration nova — ONU é registrada como equipamento
  `other` com um metadado (`equipment_subtype: "onu"`), exibida como
  "ONU / ONT" na tela.
- **Importação de Device Type YAML.** A torre/rack ganha "Importar YAML
  de equipamento" — mesmo conceito da biblioteca de tipos de dispositivo
  do NetBox: o arquivo descreve fabricante, modelo e interfaces, que
  viram portas automaticamente ao importar (RJ45 100M/1G, SFP, SFP+,
  wireless, PON). Fluxo: escolher o YAML → pré-visualizar → conferir
  fabricante/modelo/interfaces → escolher o tipo no mapa → importar.
  Exemplo incluído: `examples/device-types/mikrotik-rb911g-5hpacd.yaml`
  (Mikrotik RB911G-5HPacD — Gigabit Ethernet + rádio 5GHz 802.11ac).
- **Terminação óptica ampliada.** Antes só dava pra terminar/fundir uma
  fibra numa porta de DIO; agora também em porta PON (de ONU), SFP e
  SFP+. Continua corretamente bloqueado terminar fibra direto numa porta
  RJ45 (é elétrica) — nesse caso a fibra precisa passar por uma ONU,
  conversor, DIO ou outro equipamento óptico antes de sair por cobre.

## Atualização

Execute `apply` no servidor. **Sem migration nesta versão.** Nova
dependência: `PyYAML` (já em `requirements.txt`, o `apply`/build já
instala sozinho).

Teste sugerido:
1. Importar um KMZ que antes travava com o erro de padrão de cores —
   confirmar que agora completa e gera fibras.
2. Numa torre ou rack, abrir "Gerenciar estrutura" e conferir que abre
   direto, sem piscar.
3. Adicionar um equipamento "ONU / ONT / Outro" na torre/rack.
4. Testar "Importar YAML de equipamento" com o exemplo incluído
   (`examples/device-types/mikrotik-rb911g-5hpacd.yaml`) — conferir que
   as portas `ether1` (RJ45 1Gb) e `wlan1` (Wireless) aparecem.
5. Terminar uma fibra numa porta PON de ONU e numa porta SFP — confirmar
   que funciona, e que ainda bloqueia terminar direto num RJ45.
