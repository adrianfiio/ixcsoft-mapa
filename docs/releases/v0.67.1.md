# AFService Map v0.67.1

Backup/ponto de rollback desta rodada: tag `v0.67.0`.

Correção pequena, direto no `.gitignore`, sem tocar em código da
aplicação.

## O que aconteceu

O `apply` no servidor cancelou a atualização com:

```
✗ Existem alterações locais. A atualização foi cancelada para não sobrescrever arquivos.
?? docker-compose-monitor.yml
?? telegraf.conf
```

Esses dois arquivos não fazem parte deste repositório — são da stack de
monitoramento (Telegraf) que está sendo montada à parte, direto em
`/opt/ixcsoft-mapa` no servidor. O `apply` exige a árvore de trabalho
limpa antes de atualizar (`git status --porcelain` sem saída) exatamente
pra nunca sobrescrever ou perder algo que esteja sendo montado ali na
mão — e por isso parou, corretamente, em vez de seguir em frente.

## Corrigido

- **`docker-compose-monitor.yml` e `telegraf.conf` adicionados ao
  `.gitignore`.** O Git para de considerá-los "alteração local pendente",
  então o `apply` não barra mais por causa deles. Os arquivos em si não
  foram tocados nem apagados — continuam exatamente onde estão, só
  pararam de aparecer no `git status`.

## Atualização

Este primeiro `apply` ainda vai precisar de um passo manual único,
porque o `.gitignore` novo só passa a valer depois de já ter sido
baixado — e é justamente a sujeira atual que está impedindo o `apply` de
baixar qualquer coisa. Depois desta vez, nunca mais precisa repetir esse
passo.

No servidor, como root, em `/opt/ixcsoft-mapa`:

```bash
mkdir -p /root/monitor-staging
mv docker-compose-monitor.yml telegraf.conf /root/monitor-staging/
apply
mv /root/monitor-staging/docker-compose-monitor.yml /root/monitor-staging/telegraf.conf .
```

Isso só move os dois arquivos pra fora da pasta por alguns segundos
(tempo do `apply` rodar), sem parar nenhum container que já esteja
usando esses arquivos — containers já iniciados continuam rodando
normalmente mesmo com o arquivo de origem temporariamente fora do lugar.
Depois do `apply`, os arquivos voltam pro lugar de sempre.

Antes de mover, se quiser conferir se algo depende diretamente do
arquivo nesse exato caminho neste exato momento (por exemplo, se algum
comando `docker compose -f docker-compose-monitor.yml ...` estiver
rodando ou programado nesse instante), rode:

```bash
docker ps --format '{{.Names}}\t{{.Image}}' | grep -i telegraf
```
