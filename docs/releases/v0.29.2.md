# AFService Map v0.29.2

Correção de um erro 500 real em produção, mais o ajuste do cadastro de
equipamento fora do mapa.

## Correção crítica

A Visão geral de uma empresa projetista quebrava com erro 500 assim que
existia pelo menos um cabo desenhado com geometria real no mapa. A causa: o
cálculo de "km de cabo desenhado" usava uma função de comprimento
geoespacial sem informar explicitamente o tipo de retorno esperado
(`output_field`), o que o Django não consegue sempre inferir sozinho — e só
falhava quando havia de fato uma geometria para processar (com o queryset
vazio, antes de existir qualquer cabo, o erro nunca acontecia). Agora o
tipo é declarado explicitamente e, como proteção extra, se qualquer
geometria futura vier inválida o dashboard não quebra mais — só mostra 0 km
nesse caso, em vez de página de erro.

## Cadastro de equipamento

A página "Equipamentos" tinha um botão "+ Novo equipamento" que na prática
nunca funcionava: o formulário exigia escolher um "Projeto", mas esse campo
nunca aparecia na tela — o cadastro falhava silenciosamente, sem nenhuma
mensagem de erro. O mesmo problema afetava a edição de um equipamento já
existente.

Decisão: cadastro de equipamento passa a ser feito só pelo mapa, onde o
projeto e a posição já ficam definidos naturalmente. A página
"Equipamentos" continua disponível para ver, editar e excluir — e a edição
agora mostra o campo "Projeto" corretamente, então deixou de falhar
silenciosamente.
